# Port-backed and incremental snapshot prior art

The behavioral authority is pinned Ghostty commit `51ed437cd1a202e625feb7fd0577354d81bcc54b`. `include/ghostty/vt/io.h:18-99` defines synchronous borrowed reader/writer callback arguments and by-value `GhosttyReader` and `GhosttyWriter` descriptors. `include/ghostty/vt/snapshot.h:228-513` defines callback encoding, callback-backed decoder construction, READY, NEXT, one-shot decode, typed metadata, ownership, ordering, and failure behavior. Matching implementation lives in `src/terminal/c/{io,snapshot}.zig` and `src/terminal/snapshot/snapshot.zig`.

A writer callback must accept each complete borrowed slice; the Racket adapter copies it first and retries short port writes. A reader callback may return positive short reads, while successful zero means permanent EOF. Native framing avoids consuming bytes after FINISH. Callback false maps to native I/O error, but Racket records the first raised value or break, returns false through C, completes cleanup, and then re-raises that identical value. Failed custom ports can leave a consumed or emitted unusable prefix.

Racket CS runs FFI callbacks atomically, where port I/O cannot block safely. The installed Racket 9.2 sources `scribblings/foreign/types.scrbl:770-794`, `scribblings/foreign/atomic.scrbl:129-138`, and `collects/ffi/unsafe/atomic.rkt:73-161` establish the transition used here: the native call owns an outer `call-as-atomic` layer; the callback balances its added layer with `end-atomic` and `start-atomic`; and `call-as-nonatomic` runs continuation-barrier-protected port work. Public port-backed operations reject entry from an existing atomic region. Semaphores are acquired before the outer atomic layer, and `/enable-break` port primitives run while the surrounding break state is disabled so delivered breaks do not also report completed I/O.

READY publishes a caller-owned renderable terminal, but the native decoder borrows that terminal through FINISH or decoder free. Racket adopts it with an initial token and deferred terminal finalizer. The decoder strongly retains the terminal, while the terminal stores only the token. Terminal close rejects the attached token. FINISH, consuming failure, explicit decoder close, or decoder finalization frees or completes the decoder as required, registers the terminal finalizer, removes the token, and drops the strong reference in decoder-before-terminal order. NEXT locks decoder then terminal and copies progress before native state can replace it.

Go exposes writer encoding, reader and byte decoders, READY/NEXT/full decode, source/history/progress queries, callback rooting, and idempotent cleanup (`/home/jay/Code/go-libghostty/{io,snapshot}.go`). Its tests cover short I/O, trailers, original error identity, incremental progress, source rooting, truncation, and limits (`snapshot_test.go:56-425`). Racket follows its short-I/O and rooted-source behavior, but structurally prevents premature READY-terminal close instead of relying on documentation.

Rust models the same lifetime by consuming a configuring decoder into an `IncrementalDecoder` that owns both decoder and READY terminal; `into_terminal` abandons remaining history safely (`/home/jay/Code/libghostty-rs/crates/libghostty-vt/src/snapshot.rs:190-465`). Its checked-out revision pins a different Ghostty format and its callback adapter discards original I/O errors, so Racket uses only its ownership precedent, not its wire-format or error behavior.

Exact-name searches found no persistence snapshot callbacks in the local Python or Node bindings. Their snapshot-like operations are visible terminal projections. The designated browser spike has no settled reconnect storage, authentication, or multi-session ownership policy, so milestone 6.3 proves the native port-to-READY-to-NEXT workflow through public Racket tests and deliberately leaves browser behavior unchanged.

The private ABI represents both callback structs as a callback-sized pointer followed by userdata and checks them against `ghostty_type_json`. The pinned-header probe assigns exact function signatures for encode, callback decoder construction, READY, NEXT, full decode, getters, and multi-get; it also verifies decoder data selectors and primary/alternate screen values. Raw callbacks, userdata, allocators, numeric selectors, borrowed source buffers, and generic getters remain private.

Snapshot version 1 remains unstable and CRC32C-protected rather than authenticated. Native code supplies no total byte, row, page, or decoded-allocation bound. Callers must externally bound hostile ports. Runtime tests cover exact writer equivalence/counts, one-byte and short reads, trailing bytes, callback failures and arbitrary-value identity, incremental metadata and progress, live mutation and zero-row progress, borrow rejection and detachment, finalizers and weak roots, reentrancy and cross-lock failure, deterministic blocked-callback breaks, and subsequent native health. Racket BC and external leak/UAF instrumentation remain unverified.
