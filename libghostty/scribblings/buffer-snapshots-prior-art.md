# Buffer-based snapshot prior art

The behavioral authority is the pinned Ghostty source at commit `51ed437cd1a202e625feb7fd0577354d81bcc54b`. `include/ghostty/vt/snapshot.h:21-112,256-310,339-391,451-493` defines the unstable version-1 record stream, allocated and caller-buffer encoders, borrowed-buffer decoder, one-shot decode, continuation limit, source offset, ownership, and result codes. The matching implementation is `src/terminal/c/snapshot.zig:128-205,396-493,557-659` and `src/terminal/snapshot/{envelope,record,snapshot,continuation}.zig`.

A snapshot starts with `GHOSTSNP` and a little-endian version, then ordered CRC32C-protected records through READY and FINISH. CRC32C detects corruption but does not authenticate input. Version 1 has no compatibility guarantee. EOF before required markers, invalid framing, checksums, ordering, counts, and continuation state are invalid values. Allocation and configured continuation-limit failures retain their distinct native results. No decoder option limits total bytes, rows, or records, so the public documentation requires callers to bound untrusted input.

`ghostty_snapshot_encode_alloc` returns allocator-owned bytes that require `ghostty_free` with the same allocator and exact length. `terminal->snapshot-bytes` keeps the native output cells visible to unwind cleanup, copies the complete allocation into immutable Racket bytes, and always releases the native allocation. The caller-buffer encoder adds capacity negotiation but no public capability, so it remains private.

`ghostty_snapshot_decoder_new_buf` borrows immutable source storage until FINISH or decoder free. The Racket operation first copies its input into native storage, completes decode synchronously, then frees the decoder and source copy. Mutable Racket input can therefore change after return without affecting the restored terminal. Mutation during the call is unsupported because it can race the initial copy; callers must keep the input unchanged until restoration returns.

One-shot native decode is transactional and returns a newly owned terminal only after FINISH. Caller-visible native output cells and a single producer/adopter/wrapper ownership token keep the returned pointer under unwind cleanup through wrapper adoption. The wrapper adds a fresh lock, render helpers, effect state, callback roots, idempotent close, and finalizer. Snapshot data does not recreate Racket handlers or other host resources. Partial setup and breaks release every initialized native resource exactly once; ordered native release suppresses breaks only for its short cleanup interval.

The native decoder accepts transport bytes after FINISH and reports their boundary through source offset. The curated one-shot Racket operation instead requires exactly one snapshot and rejects trailing or concatenated data. Port framing, source offsets, reader and writer callbacks, READY/`next` incremental history, progress queries, and public decoder lifecycles belong to the next snapshot facility.

Go exposes allocated and caller-buffer encoding, copying and pinned byte decoders, reader/writer callbacks, one-shot and incremental restoration, typed metadata, and idempotent decoder cleanup (`/home/jay/Code/go-libghostty/snapshot.go:164-582`). Its tests cover allocated/buffer/writer equivalence, copied ownership, continuation restoration, incremental history, pinned lifetime, trailing transport bytes, callback failures, truncation, and limits (`snapshot_test.go:56-423`). Racket follows its copied-input lifecycle while omitting transport mechanisms from this facility.

Rust exposes writer, allocated, and caller-buffer encoding plus borrowed-buffer, reader, one-shot, and lifetime-checked incremental decoders (`/home/jay/Code/libghostty-rs/crates/libghostty-vt/src/snapshot.rs:99-493`). Its ownership model supports the same private decoder-before-input cleanup order, but its local revision pins a different Ghostty commit and describes different READY/FINISH authentication. Racket follows the current pinned C headers rather than that format prose.

Exact-name searches found no binary persistence interface in the local Python or Node bindings. Their screen or row “snapshots” are render projections, not terminal persistence. The browser-terminal example likewise has no reconnect persistence policy, so this facility adds no browser behavior.

The public tests cover ground and unfinished round trips, active and alternate screen state, terminal modes, large styled-Unicode scrollback through deterministic re-encoding, source/restored independence, copied lifetime, fresh effects, continuation limits and restored tracking, malformed/version/checksum/mid-record/order/trailing inputs, GC during restored use, repeated cleanup, serialization, close races, asynchronous-break stress, and a source-close restoration workflow. Break stress can detect common crashes but cannot prove cancellation-time leak freedom. Native allocation-failure injection and an external leak detector remain unrun; cleanup is additionally established by the explicit ownership transitions and caller-visible output cells.
